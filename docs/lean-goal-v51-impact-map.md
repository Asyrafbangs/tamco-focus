# Lean Goal v51 implementation impact map

## Approved change

The attached 10 August 2026 Goal instruction supersedes the v50 authoring experience while preserving the single Goal data model, lifecycle records, evidence, audit history, permissions, monthly check-ins, quarterly reviews, notifications, storage and unrelated application behaviour.

## Database and security approach

- Add only nullable/backfilled columns to `goal_success_measures`; retain v50 columns for historic versions and existing check-in calculations.
- Add lean create/save/agreement RPCs that use the existing `goals`, `goal_versions`, `goal_success_measures`, `goal_milestones`, `goal_participants`, `goal_agreements`, notification and audit tables.
- Keep direct table writes denied by RLS. Every mutation authenticates the actor, checks owner/manager authority, locks the Goal/allocation where required, validates optimistic versions and writes audit history transactionally.
- No hosted Supabase link, deployment, remote, prototype seed injection or production-data rewrite is in scope.
