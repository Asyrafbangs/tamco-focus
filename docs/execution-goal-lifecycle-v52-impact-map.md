# TAMCO Focus v53 — execution and Goal lifecycle impact map

Date: 10 August 2026  
Source: approved product boundary supplied on 10 August 2026  
Scope: Task execution and Goal management only. The future ESH finding/action system is explicitly excluded.

## Product boundary

TAMCO Focus owns the shared execution record: Capture, Available, Active, Pause/Resume, Reassign, Barrier, Complete and Cancel. A future specialist module may link its own business object to a Task through nullable generic source fields, but it must not create a parallel task engine.

Goals remain a separate performance-management domain. Their cadence is employee/session based; individual Goals contribute snapshots to a monthly or quarterly session rather than creating independent approval workflows.

## Data and security decisions

- All schema changes are forward-only migrations. Existing migrations are not rewritten.
- Historical checklist items, barriers, notifications, Goal check-ins and audit events are retained.
- Direct client mutation remains prohibited for lifecycle state; UI calls security-definer procedures that lock rows, verify authority/version and audit in one transaction.
- Shared is always derived from incomplete checklist assignment and parent ownership; no duplicate Shared Task rows are created.
- Generic source identifiers deliberately have no cross-table foreign key because the external module owns the source record.
- A Goal session links to the existing per-Goal check-in snapshot rows, so cadence truth gains an aggregate without creating a second Goal history.
- `department_only` is the only active governance mode in this release. `organization_hierarchy` is stored as a future configuration value but does not invent a reviewer where the reporting hierarchy is absent.

## UI impact

- Task drawer: cancellation authority/state feedback and reassignment workload-review result.
- Work/My Team: real Major Project proposal attention rows and decision drawer.
- Capture: proposal submissions return to an inspectable proposal record.
- Goals: monthly and quarterly employee-session cards/drawers, plan allocation/finalisation, explicit Complete and Cancel actions, required revision reason, exact success-measure presentation.
- Existing Task/Goal detail routes, authentication, local Supabase, attachment storage and unrelated navigation remain unchanged.

## Request-engine defects found while verifying

- `getMyAttention` resolved every request's subject through `task_id`. A request raised against a Goal has none, so one of them failed the whole subject lookup and every card on the screen — Task requests included — rendered the heading "Work", while the Goal request's own control pointed at `/work?task=null`. Personal attention now reads `action_requests_overview`, which resolves either subject in one query.
- Goal support notifications carry `entity_type = 'barrier'` with no task, and fell through every branch of the link resolver to My Day. They now open the Goal.
- Requests whose source has gone terminal are excluded from personal attention, matching the cleanup the cancellation path performs.
- A Goal support request ranks with the other requests rather than falling through to `awareness`.
- The Goal drawer's Sessions control carried an `aria-label` that did not contain its visible word (WCAG 2.5.3), and a second control in the same dialog shared it.

## Superseded database procedures — retired

Dropped in `20260811001000_v53_retire_superseded_goal_procedures.sql`, once the gates were green and the suites below had moved onto the replacements. Each was `security definer` and granted to `authenticated`, so leaving them would have left a second reachable way to write into the Goal engine: per-Goal monthly records the session model cannot see, version agreement outside the lean flow, and an ending that does not say which kind of ending it was.

Four tests were retired rather than migrated, because what they asserted no longer exists: the per-Goal overall update, structured numeric measure authoring, per-Goal monthly idempotency, and the per-Goal quarterly/year-end record. Sections 11, 14, 17 and 20 replaced each of them.

Two earlier removal candidates were withdrawn on re-checking, because both are called from SQL rather than from the application: `post_task_update_v34_internal` (called by `post_task_update`) and `post_goal_milestone_update` (called by the v53 `post_goal_milestone_checkin`). Neither is dead.

## Explicitly out of scope

- ESH findings, hazards, audits, risks, inspections, incidents and chemical-domain records.
- A new management module or parallel Task implementation.
- Hosted Supabase, deployment, Vercel, GitHub remote or push.
